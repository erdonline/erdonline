# 如何使用角色与 SQL 审批

团队一起改模型时，谁能改、谁能把 SQL 落到库，需要分工。这篇走「存版 → 提交工单 → 审批」主路径。

> **目标**：用项目角色约束改模型；用审批约束落库 SQL。  
> **前置**：已登录的团队（或个人）项目；两人以上时审批链路更直观。  
> **边界**：这是**项目级**权限，不是完整企业 IAM / SSO 替代品。细节见 [安全模型](../security-model.md)。

## 角色（你会用到的分工）

| 角色倾向 | 典型动作 |
|---|---|
| 成员 | 改模型、提变更 |
| 审批人 / 负责人 | 查看 SQL、通过或拒绝 |
| 管理员 | 成员与数据源等管理 |

具体菜单名以当前界面为准。

## 步骤（审批主路径）

1. 在设计器完成结构变更，并 [保存版本](./save-version-and-diff.md)。  
2. 在 **版本管理** 中，在对应版本行发起 **提交工单**（SQL 审批）。  
3. 指定审批人，提交。  
4. 审批人打开 **待审批 / 工单** 列表，查看 SQL 明细。  
5. 选择 **通过** 或 **拒绝**（破坏性操作会有确认）。

## 成功时你会看到什么

- 发起后出现待审批记录；审批人侧能打开 SQL 正文。  
- **通过**后状态按产品规则更新；若执行失败，**不会**伪装成「已通过」。  
- 拒绝或撤销后，发起方可看到结果并决定是否修改再提。

## 常见问题 / 排障

| 现象 | 可尝试 |
|---|---|
| 找不到审批入口 | 确认账号角色；在版本行找 **提交工单**；顶栏看待审批 / 工单 |
| 个人项目不想走审批 | 可以；个人场景可只走版本 diff |
| 实时协作者看不到对方光标 | 自托管时确认协作端口可达；见 [部署指南](../deployment.md) |
| 希望用公司 SSO | 默认产品内账号；联邦能力以实例配置与工程文档为准 |
