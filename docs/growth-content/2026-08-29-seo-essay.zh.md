Search Console 告诉我们排上去了。新加坡地区平均排名 1。三个月累计 42 次展示，**0 点击**。不是点击率低，是一次都没有。

十二天、一轮工程改动之后再取数，同一个资源：2 点击 / 103 展示 / CTR 1.9% / 平均排名 62.7。拆到页面维度，出现了两行本不该同时存在的数据：

| 网址 | 点击 / 展示 | 平均排名 |
|---|---|---|
| `https://www.erdonline.com/` | 1 / 90 | 61.3 |
| `https://www.erdonline.com/compare` | 1 / 8 | 约 2–3 |

一个页面在真正有人搜的词上压在第六页，另一个页面在几乎没人搜的词上稳坐第二。这时候最自然的反应是「内容不够，多写几篇」——几乎所有 SEO 文章都这么教。这个判断是错的，跟着它走会白扔一个月。

真正的病根是：我们这个站**只有一个身份**。八个营销 URL、sitemap、hreflang、JSON-LD 一样不缺，但每一个 URL 交给 Google 的首字节，是同一份 HTML。

## 一条命令就能确诊

我们的主站是 UmiJS 纯前端渲染，托管在 Cloudflare Pages。在动任何脑子之前，先 curl 一下爬虫实际拿到的东西：

```bash
curl -sL https://www.erdonline.com/catalog | grep -E '<title>|rel="canonical"'
```

好几个月里，这条命令吐出来的是首页的 `<title>`，以及 `<link rel="canonical" href="https://www.erdonline.com/">`。`/compare` 一样，`/en` 一样，`/demo` 一样。然后还有更狠的一条：

```bash
curl -sI https://www.erdonline.com/__seo_health_nonexistent_path__
# HTTP/2 200
```

一个从来不存在的路径，返回 200，body 是首页。这就是软 404。而软 404 一旦存在一个，就等于存在无穷多个。

Googlebot 看到的不是「一个有八个页面的站，外加一点噪音」。它看到的是**一个页面挂在无限多个地址上**——这正是低质量站点的特征。它的应对方式很朴素：留一个 URL，其余悄悄丢掉。

排名从来不是瓶颈。「是一个独立的页面」才是。

## 两个平台默认行为，都写在文档里，都容易漏

两个成因都不冷门。都是我们自己写下的，然后再也没看过。

**一条通配反代。** `public/_redirects` 里有 `/* /index.html 200`。这行是所有 SPA 教程都让你加的，为了让前端路由在硬刷新时不 404。对 `/project/1234` 这种登录后才可达、本来就不该被索引的页面，它是对的。对 `/compare` 这种存在的唯一意义就是被索引的页面，它是毁灭性的。

**根目录没有 `404.html`。** Cloudflare Pages 有一条官方规则，很多人栽在这儿：构建产物根目录**没有** `404.html` 时，Pages 假定你是单页应用，于是所有没命中静态文件的路径统统 `200 + index.html`。放一个 `404.html` 进去，这个自动 SPA 模式就关掉，未命中路径返回真正的 HTTP 404。一个文件，无限软 404 到此为止。

另外有三个小坑，每个都花掉我们一次部署，而且都是没人会写下来的那种：

- 反代目标写 `/index.html` 不行。Cloudflare 会把 `*.html` **308** 到去掉扩展名的形式，于是一条本该无感的 rewrite 变成了一次跳转到 `/`。
- `/catalog/* → / 200` 里的通配会匹配到 `/catalog/`（空段），把我们刚生成好的列表页壳子悄悄盖掉。必须写成 `/catalog/:id`。
- 未知模板 ID 我们最初送到一个占位壳 `/catalog/_item`。因为它是个目录，Cloudflare 把 `/catalog/某个乱写的ID` **308** 到了 `/catalog/_item/`——我们在清理垃圾 URL 的过程中，亲手造出了一个全新的、可被抓取的垃圾 URL。正确做法是把未知 ID **200 到 `/catalog/`**（目标本身已带斜杠，没有可 308 的余地），并把 `_item` **301** 掉。

这三条的共同点是：**差一点就对了**。这也正是这类 bug 的性质——站点对真人完全正常，对爬虫完全不可索引，而且你把 React 代码读一百遍也发现不了。

## 四份产物，一个真相源

修法本身不新鲜：构建期为每个公开路径写出独立壳子——`dist/catalog/index.html`、`dist/compare/index.html`、`dist/en/compare/index.html`……每份带自己的 `<title>`、canonical、hreflang 和 JSON-LD；同时把这些精确路径从 `_redirects` 里删掉，让静态文件赢。

这是显而易见的那一半。值得抄走的是另一半：怎么让它别烂掉。

新增一个公开路由，要求**四份产物同时对齐**：

1. `sitemap.xml` 里的 URL 列表
2. 需要预渲染壳子的路径集合
3. 其余路径的 Cloudflare `_redirects` 规则
4. 自部署 Docker 的 nginx `map`

四个文件，纯手工维护，而加路由的人当时脑子里只有 React Router。它一定会漂。我们的就漂了。

所以现在这四份全部由同一个模块 `frontend/scripts/seo-config.mjs` 导出并派生：`SITEMAP_PATHS`、`PRERENDER_PAGES`、`CF_SPA_REDIRECT_RULES`、`NGINX_SPA_URI_REGEXES`，加上 `marketingHreflang()` 和 `jsonLdForPage()`。构建脚本消费它，一趟写出 `sitemap.xml`、`robots.txt`、`_redirects`、`_headers`、`404.html` 和所有壳子。加一个路由 = 一个数组里加一项。「sitemap 和 redirects 不一致」这个错误，现在犯不出来了。

那个文件同时也是踩坑知识的存放处——注释就贴在它解释的那条规则旁边，其中一条大意是：*别在这儿用 `/catalog/*`，我们试过，Cloudflare 会这样。* 记录踩坑的注释配得上它占的行数；解说下一行代码在干什么的注释配不上。

## 两个只在纯前端站点才会有的 bug

壳子上线之后，冒出两个服务端渲染站点根本不会有的问题。

**hydrate 和壳子抢 `<title>`。** `/catalog/demo-authz` 首屏预渲染是对的，然后前端启动，`CatalogLayout` 无条件调了 `usePageSeo(catalog.seo.*)`——几百毫秒后，详情页的标题被**列表页**的标题覆盖掉。预渲染是对的，是我们自己的应用把它改错了。在 CSR 应用里做逐路径预渲染，客户端那个 SEO hook 就必须知道自己在哪个页面上，否则你等于造了两套系统，对 `<title>` 各执一词。现在：列表才套列表摘要；详情等 API 返回后写 `{名称} — ER 图模板`，canonical 指向 `/catalog/:id`。

**每个页面都声称自己是那个应用。** 我们的 JSON-LD 生成函数只把 `url` 参数化了，`@type` 一直是 `WebApplication`。八个不同的页面，各自宣布自己是「位于站点根目录的那个应用」——结构化数据在直接顶撞我们刚修好的 canonical。现在按路径分型：`/` 是 `WebApplication`，模板列表是 `CollectionPage`，官方模板详情是 `ItemPage`，其余营销页是 `WebPage`。

## 标题的问题，是承诺的问题

排名第 1、点击 0，不是排名失败。是这段摘要听起来不像搜索的人要找的东西。

我们原来的标题是品牌先行。而搜索的人要办的事不是「了解一个品牌」，是「现在，在浏览器里，画一张 ER 图」。查询报告写得明明白白：`erd online`、`erd diagram online`、`make|create|draw erd online`。于是 `<title>` 改成任务先行——`Draw ER Diagram Online — Free Editor | ERD Online`——description 用一句实话覆盖整个意图簇：draw、ERD editor and maker、entity-relationship models。

有三件事我们**故意不做**，现在写进了 `docs/landing.md` 当规则，而不是留给临场判断：

- **不写「file viewer」。** 这是个搜索量很大、听起来也很像的词。我们支持 ERD / PdMan / DBML 导入，但没有专门的文件查看器。排上一个自己满足不了的词，换来的是一次访问加一次跳出。
- **不点名 Google Draw。** 对照页点名 draw.io，因为那里有真实的技术主张——draw.io 里一根线就是一根线，ERD Online 里的关系带外键语义。没真做过对比的产品，不点名。
- **不堆非英文查询。** 报告里能看到一批非英语查询，堆上去能涨展示。但我们没有那个语种的产品体验，那种展示不是收益。

H1 保持不动，仍然是「**数据库设计的 Git + Figma**」。`<title>` 和 H1 现在故意不一致：`<title>` 回答一个查询，H1 回答「这是什么、我为什么该在意」——写给已经进来的人。把两者都压成关键词，等于丢掉后一份职责，而且读起来像 2011 年的落地页。

## 把爬虫视角变成测试

这类失效是静默的，所以唯一靠得住的修法是断言。`scripts/seo-index-health.mjs` 每天在 CI 里跑，直接打线上：

- `/`、`/demo`、`/catalog`、`/compare`、`/docs/`、`/docs/roadmap` 每一条：HTTP 200、`text/html`、`<title>` 非空、meta description 非空、有 canonical、无 `noindex`。
- `/robots.txt`：200、content-type **不是** `text/html`（robots.txt 以 HTML 返回，说明 SPA fallback 把它吞了）、含 `User-agent: *`、含绝对 URL 的 `Sitemap:`，并且**不含** `content-signal:`——最后这个字符串是判断「平台注入的默认 robots.txt 仍然压着你自己那份」的办法。
- `/__seo_health_nonexistent_path__`：必须 **404**。软 404 这个回归，钉成一条断言。
- `/compare`、`/catalog`、`/demo`、`/login`：必须仍然 **200**。因为修软 404 最顺手的做法，就是顺便把真路由弄坏。
- `sitemap.xml`：能解析、至少一条 `<loc>`、前 20 个 URL 可达。

构建期还有 `yarn test:seo-static`（不跑完整构建就校验同一份配置），以及生产冒烟里一条测试，名字就叫 `crawler first HTML uses path canonical (not homepage)`。我们上线了好几个月的那个 bug，现在在测试文件里有名字了。

同一轮还有两件不直观的事，值得单独说：

**只加缓存头没有用。** 首页返回 `CF-Cache-Status: DYNAMIC`，TTFB 约 1.6s（文档站 3.8s），同时 Search Console 提示展示次数在掉。我们给 HTML 壳子加了 `Cache-Control: public, max-age=0, s-maxage=600, must-revalidate`。没有变化——Cloudflare Pages 默认把 `text/html` 当动态内容，你还必须在后台建一条 Cache Rule，让 HTML 变成 eligible for cache。这个依赖现在写成 `_headers` 里的注释，因为一份静默不生效的头文件，比没有头文件更糟。

**尾斜杠只选一种形式，四个地方全部对齐。** 文档站当时的状况：canonical 不带斜杠、sitemap `<loc>` 不带斜杠、宿主 308 到带斜杠、旧路径 301 到不带斜杠的形式——于是一个老 URL 要先 301 再 308 才能落地。改法：`trailingSlash: true`、重定向目标带斜杠、sitemap `<loc>` 带斜杠、`/search` 与博客标签/归档页从 sitemap 里去掉。一跳到位。

## 我们停掉的事

停掉「请求编入索引」。我们对 `/catalog` 点了两次，两次都撞上 Search Console 的 reCAPTCHA 报错，什么都没进队列。手工提交是催一下，不是机制；把它当成进展，只会掩盖产物本身还是错的这件事。先修产物，再提交 sitemap，然后等。

我们还提前定好了「什么情况下改战略」。locale 路由那份 ADR 的决定是：英文营销页先按 CSR 上线，配 sitemap 和 hreflang；触发条件写死——**上线 90 天后，若 `/en` 在 Search Console 里仍未被索引，就给营销路由上静态导出**。在需要它之前就把触发条件写下来，是让「我们是不是该上 SSR？」不再每两周凭感觉重吵一遍的唯一办法。

那份 ADR 更值得看的是它**拒绝**了什么。全站 `/en/*` 路径化要动：60 条路由、39 个文件里 76 处 `history.push`、E2E 里 236 处 `page.goto`、16 个含前端 URL 的后端文件，以及已经贴到别人聊天记录里、不可变的只读分享短链 `/s/:token`。而能从中受益的页面——`/project/**`、`/design/**`、`/home`——全在登录墙后面，一点搜索价值都没有。所以：营销页加前缀，其余一律不加。需要改的站内链接点：约 21 处。

## 老实报数

今天的状态：`/catalog`、`/compare`、`/en/compare` 已收录；`/en/catalog` 是「已发现 - 尚未编入索引」；文档站英文 sitemap 提交成功，已发现 66 个网页。三个月自然搜索点击总数：**2**。

这不是一篇流量案例。索引以周为单位移动，把一根曲棍球棒曲线挂在十二天的工程改动后面是不诚实的。能报的结论只有一个：**爬虫看到的这个站，现在是对的、每天被断言、而且扩展起来很便宜**——这是任何内容投入能开始复利之前，必须先为真的那件事。

## 可以直接抄的清单

如果你也在跑纯前端渲染的站点，这几条值得花半小时：

1. `curl -sL <一个非首页的 URL> | grep -E '<title>|canonical'`。看到首页，别往下读了，先修这个。
2. `curl -sI <你的域名>/__definitely_not_a_real_path__`。返回 200 就说明你有无穷多软 404。Cloudflare Pages 上，往根目录放一个 `404.html`。
3. 删掉通配反代。把真正需要 200 的 SPA 路径逐条列出来，其余全部 404。
4. 让 sitemap、预渲染壳、宿主 rewrite、自部署 rewrite 从同一个模块派生。加路由应该只改一行。
5. 检查 hydrate 有没有把构建期刚写好的逐路径摘要覆盖掉。
6. 检查 JSON-LD 的 `@type` 是真的按页分型，还是首页那个类型换了个 `url`。
7. 尾斜杠只选一种。canonical、sitemap `<loc>`、宿主跳转、旧路径重定向，四处必须一致。
8. 把以上每一条都变成对线上环境的每日断言。这类 bug 天生静默。
