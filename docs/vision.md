# 产品愿景 / Vision

> 本文回答一个问题：这个项目要成为什么，以及为什么。
> 它是所有功能取舍的最高裁判。修改本文需要维护者共识。

## 一句话定位

**数据库设计的 Git + Figma，AI 时代数据结构的开源事实源** —— 把版本管理与实时协作带入数据库建模；projectJSON 与版本体系让人和 AI agent 都以同一份事实源读写数据结构。

定位升级依据见 [ADR-0012](./adr/0012-ai-era-data-structure-platform.md)（已接受 · 选项 B）。公开 API/MCP 见 [ADR-0013](./adr/0013-public-api-mcp.md)（📋 规划中）。

## 为什么是这个定位

数据库建模工具的生态位分布：

- **极简工具**（dbdiagram.io）：好看好用，但无协作、无版本、闭源
- **通用画图**（drawio）：免费灵活，但不懂数据库语义
- **单机桌面**（PDManer、Navicat）：功能重，但无协作、体验老旧

**"协作化的数据库设计"是唯一空着的生态位**，而本项目已具备别人没有的资产：每次变动自动生成版本并支持差异比对、三级权限与审批流、多数据源正反向工程。我们把长板做长，而不是在别人的生态位里内卷。

## 三层用户价值（评判一切需求的标准）

1. **首次接触的人**：30 秒内觉得惊艳 —— 决定传播
2. **深度用户**：建模工作离不开，换工具成本极高 —— 决定留存（靠版本 + 协作锁定）
3. **潜在贡献者**：读代码觉得讲究，愿意提 PR —— 决定生态（靠现代技术栈与工程质量）

任何需求评审先问：它服务哪一层？都不服务的，不做。

## 北极星指标

**每周产生版本保存的活跃建模项目数**（须为**非空 diff** 的版本保存；空 changes 书签式存版允许但不计北极星，见 [ADR-0022](./adr/0022-dual-layer-consistency.md)）。

Star 数是滞后的虚荣指标；这个指标才是产品真实生命力。辅助护栏指标：CI 门禁强度、核心模块测试覆盖率、首屏体积、核心旅程耗时（见 `performance-budget.md`）。当前季度的北极星杠杆见 [roadmap.md「下一季只做三件事」](./roadmap.md#下一季只做三件事北极星杠杆)。

## 我们不做什么

- 不做移动端 / 桌面客户端 —— 建模是桌面浏览器场景，早期分散精力必死
- 不做闭源云版 / 商业化分心 —— 先赢开源口碑，商业化是赢之后的问题
- 不做 AI 噱头 —— 不包装对话式黑盒魔法；AI 能力以「开放 API/MCP + 版本事实源 + 可审计」的平台形态交付，agent 是 projectJSON 的一等公民
- 不做 dbdiagram 复刻 —— 极简工具生态位已被占，我们打协作、版本与开放事实源的差异化
- 不在已淘汰的技术栈上追加投资 —— 止损是工程决策的一半

## 体验设计原则

见 [design-principles.md](./design-principles.md)。所有交互改动必须过这六条原则的检查。

**设计器是主战场之一**（与 Home / 落地同为壳层）：关系图本身的可读与「敢分享」美学、自动布局质量，与版本/协作能力并列为产品杠杆；本季投注权重见 [ADR-0016](./adr/0016-experience-first-shareable-diagram.md)。

## 技术路线要点

- 设计器画布迁移至 **ReactFlow**（Strangler 策略，新旧并行后切换）
- 后端 Spring Boot 先升 2.7 稳定，3.x + JDK 17 作为独立里程碑，两大变更不并行
- UI 收敛至 Ant Design 一套；JSON 处理统一 Jackson
- 核心数据格式 projectJSON 实行 schema 版本化，永不原地破坏（见 `data-format.md`）
