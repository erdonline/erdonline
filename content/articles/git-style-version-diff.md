## 开场：一次真实的「谁动了 user 表」事故

周五下午，测试环境连不上库。排查下来是 `user` 表的 `status` 字段从 `TINYINT` 被改成了 `VARCHAR`，线上脚本批量更新直接报错。群里三个人互相 @：「不是我改的」「我只动了索引」「Navicat 里早就改回去了啊」——但**没有任何一条记录**能证明谁在什么时间、把什么改成了什么。

这不是极端个案。只要表结构会演进，就会反复遇到同一类问题：**当前态在，历史没了；口头对齐在，证据没有。** 和代码一样，数据库设计也需要「谁、何时、改了什么」的可追溯性——只是大多数 ER 工具从未把这件事当成一等公民。

## 为什么现有的工具管不了这件事

先把机制说清楚，不针对某一家产品：

| 方式 | 能回答的问题 | 管不了的事 |
|---|---|---|
| draw.io / 通用画图 | 「现在长什么样」 | 没有版本链；改完即覆盖，无法 diff |
| Navicat / 客户端导出 | 「当前 DDL 快照」 | 需人工导出、命名、归档；无项目内 diff UI |
| dbdiagram 等极简建模 | 「当前模型长什么样」 | 聚焦当前态与导出；协作与版本叙事不是主路径 |
| 纯 SQL 迁移脚本（Flyway 等） | 「已落库的变更历史」 | 管的是**已执行 DDL**，不是设计阶段的 ER 语义与字段级 diff |

缺口在于：**设计阶段的表/字段/关系变更**，需要像 Git 一样——每次有意义的改动自动成版，任意两版之间能看 diff，而不是靠人记、靠文件名猜。

## 把 Git 心智搬进建模：版本快照是什么

[ERD Online](https://github.com/erdonline/erdonline) 把「保存版本」做成建模工作流里的常规动作，而不是导出文件的额外步骤：

1. **在项目里改表**——增删字段、改类型、调关系，画布与 projectJSON 同步更新。
2. **点「保存版本」**——输入版本号（如 `1.0.1`）与说明，系统为当前 projectJSON 打快照。
3. **版本列表按时间排列**——可给里程碑打 tag，后续比对、回滚、协作都以版本号为锚点。

这和 Git 的 commit 心智一致：**当前工作区可以乱改，落盘的是一条不可篡改的快照链。** 区别是快照存的是结构化 projectJSON（表、字段、索引、关系），不是 `.sql` 文本堆。

> 诚实说明：若本次保存相对上一版**没有任何实质变更**（空 diff），系统允许存版作书签，但**不计入**我们关注的「有效版本保存」指标——我们鼓励的是「改动了再存」，而不是刷版本号。

## diff 可视化：两个版本之间到底改了什么

光有版本列表还不够。真正救命的是 **diff 面板**：选「初始版本」和「目标版本」，一眼看到：

- 哪些**表**新增或删除；
- 哪些**字段**增删改（含类型、主键、备注等语义）；
- 哪些**关系**变动。

不需要把两份 DDL 贴进 Beyond Compare 人工 eyeball。设计评审、事故复盘、和 DBA 对齐，都可以指着 diff 说：「就是这两处改动导致了下游脚本失败。」

这也是我们把「每周产生**非空 diff** 的版本保存数」当作北极星的原因：**存版 + 看 diff** 才算完成一次有价值的建模闭环，而不是把版本号当文件夹名用。

## 30 秒亲手验证（免注册）

不用注册、不用装客户端，打开 demo 即可走通「改表 → 存版 → 看 diff」：

1. 打开 demo，进入示例项目的设计器。
2. 任选一张表，新增或修改一个字段（例如给 `user` 加一列 `nickname`）。
3. 点击「保存版本」，填版本号后确认；打开版本管理，选两个版本做比对，查看 diff 面板。

## 不止 diff：协作、审批流与回滚

版本 diff 是入口，团队场景还需要：

- **多人协作**：同一项目并行改模型，变更通过版本链汇聚，而不是文件传来传去。
- **三级权限与审批流**：成员改结构、负责人审、管理员兜底——适合「谁可以动生产库对应的设计」。
- **回滚到历史版本**：选定目标版本，把 projectJSON 恢复到该快照（落盘前仍有确认步骤）。

以上能力在开源版均已提供；细节见[官方文档]({{DOCS}})，此处不展开配置截图。

## 开源与自部署

- **许可**：MIT，可商用、可 fork、可内网部署。
- **一键起栈**：仓库根目录 `docker compose up -d`，MySQL + Redis + 前后端按 compose 编排启动（见 [部署文档]({{DOC:deployment}})）。
- **开放格式**：核心数据为 projectJSON，schema 版本化，承诺**仅加法、不破坏**已有字段——便于自建工具、AI agent 或 MCP 集成读写同一份事实源。
